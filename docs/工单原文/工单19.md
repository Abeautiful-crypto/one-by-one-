任务描述
<w:tcPr><w:tcW w:w="8444" w:type="dxa"/><w:vAlign w:val="top"/></w:tcPr><w:p w14:paraId="6EA737ED"><w:pPr><w:pStyle w:val="6"/><w:spacing w:before="150" w:line="219" w:lineRule="auto"/><w:ind w:left="112"/></w:pPr><w:r><w:rPr><w:spacing w:val="-2"/></w:rPr><w:t>一、任务背景
当前数字人项目基于开源仓库 awesome-digital-human-live2d，前端使用 Three.js / Live2D 实现数字人展示与交互，后端核心能力由 Python 实现，主要负责：
•    WebSocket 实时通信
•    语音对话处理（ASR → LLM / Coze → TTS）
•    多轮对话上下文维护
•    数字人状态与事件驱动
随着功能复杂度提升，现有 Python 后端在以下方面存在明显问题：
•   WebSocket 连接不稳定，断线后恢复能力弱
•    流式对话过程中容易出现状态错乱
•    沉浸模式下用户打断后逻辑混乱
•    并发场景下会话互相污染
•    代码结构偏脚本化，不利于排错与扩展
因此，本任务要求使用 Go（Golang）对现有 Python 后端核心逻辑进行完整重构，在不修改前端代码、不改变前端行为的前提下，使系统能够稳定支持数字人实时语音与文本对话。

3.1 WebSocket 服务能力
后端需实现一个 WebSocket 服务，用于与前端建立长连接，负责所有实时数据通信。

后端需支持纯文本对话模式，用于测试与基础交互。功能要求
•    接收前端发送的文本消息
•    将文本转发至 Coze / LLM 服务
•    支持多轮上下文对话
•    将生成的回复实时返回给前端行为要求
•    上下文需与当前会话绑定
•    不同会话之间上下文不得混用
•    支持连续多次提问
3.4 语音对话完整链路（核心功能）
后端需完整实现数字人语音对话流程：
语音输入 → ASR → LLM / Coze → TTS → 语音输出
功能要求
•    支持接收前端发送的音频数据
•    调用 ASR 服务将语音转换为文本
•    将文本发送至 LLM / Coze 服务
•    支持流式获取 LLM 回复
•    将回复文本转换为语音（TTS）
•    将生成的音频数据推送给前端播放行为要求
•    支持流式返回（逐段返回文本或语音）
•    支持在生成过程中被用户打断
•    打断后需能正确终止当前链路

3.5 沉浸模式支持
后端需支持沉浸模式下的实时交互特性。功能要求
•    支持边说边生成、边生成边播放
•    支持用户在数字人说话过程中插话
•    支持立即中断当前生成与播放行为要求
•    中断后不得继续推送旧数据
•    中断后系统状态需回到可用状态
•    不得出现多个回复同时输出的情况
3.6 会话与状态管理
后端需为每个 WebSocket 连接维护独立会话状态。会话状态至少包含
•    对话上下文记录
•    当前交互模式（普通 / 沉浸）
•    当前是否正在生成回复
•    当前是否正在播放语音行为要求
•    会话状态仅对当前连接可见
•    不得出现状态串线
•    状态变更需及时反映到后续逻辑
3.7 数字人事件推送
后端需向前端推送数字人相关事件，用于驱动动画或状态变化。
事件示例
•    开始说话
•    停止说话
•    被用户打断
•    对话结束
