本工单面向网约车订单，围绕订单管理、订单详情、订单跟踪、派单设置四大能力进行后 端实现与优化。目标是在高并发、强一致与强实时的业务场景下，提供低延迟的查询与操 作接口、可靠的订单状态机与审计、稳定的实时轨迹推送与轨迹回放、以及可配置可灰度 的派单规则体系，满足日常运营与峰值调度需求，并为后续数据治理与风控留出可观测与 扩展空间。
技术说明
架构与框架：Gin 或 go-zero HTTP 网关层，分层设计 Controller Service Repository， 内聚订单域逻辑
存储与索引：MySQL 作为主存，事务与状态机落库；建立来源 状态 创建时间 车牌号联 合索引；轨迹点冷热分层存储，热数据 Redis，冷数据 MySQL
缓存与队列：Redis 用于列表缓存、幂等键、地理位置索引 GEO、实时态通知；Redis Stream 用作轻量事件总线
实时通道：WebSocket 推送订单状态与司机位置，支持断线重连与补发；服务端维护订阅 关系与节流
派单引擎：可插拔策略与可配置参数，候选司机池由后台配置；基于时间窗可用性校验与 GEO 距离计算，并应用多维评分模型
可观测与审计：Zap 结构化日志，Prometheus 指标，审计表记录关键变更，链路 ID 贯 穿全链路
代码规范：Go1.20+，error 包装、上下文传递、接口幂等、事务边界清晰，单测覆盖核 心路径
操作流程
设计订单状态机与订单表结构，补充二级索引与审计表；实现查询筛选与排序语义并验证 执行计划
实现订单取消与改派接口，加入幂等与权限校验；落审计与事件通知，确保事务内状态一 致
建立司机位置上报接口与 WebSocket 推送通道，落地轨迹持久化与轨迹回放查询；实现 断线重连与补发

派单规则落地为可计算模型：
a 依据乘客用车时间距离当前时间的先后排序优先分配；
b 校验司机在用车时间前后无订单冲突且可服务；
