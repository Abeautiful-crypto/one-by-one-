## 三、订单状态机（工单11/15/16/17）

```
pending(待接单) → accepted(已接单) → arrived(到达上车点) → picked_up(接到乘客)
  → ongoing(行程开始,启动计费) → arrived_dest(到达目的地,出账单)
  → billed(账单确认) → completed(结算完成)
pending/accepted/arrived/picked_up/ongoing ──取消──→ cancelled(含空驶补偿)
```

所有流转使用 **DB 条件更新**（`WHERE status=?`）保证原子性；每次变更写审计 + 事件总线广播。

## 四、工单实现要点

### 工单11 订单中心与派单
- **派单评分**：`score = wGeo*距离分 + wRating*服务评分 + wTimeWindow*时间窗 + wAcceptRate*接单率`
  - 规则a：用车时间紧急度参与排序（2小时窗衰减）
  - 规则b：司机已有订单与用车时间 ±90min 重叠 → 直接排除（跨库兼容，不用数据库日期函数）
  - 规则c：白天 7~22 时 / 夜间不同超时参数（60s/90s 默认）
  - 规则d：候选司机池后台配置（`DriverPool`），按城市灰度，版本化+一键回滚
- **决策理由**落库 `dispatch_logs`（如 `距离0.6km(距分0.88) 服务评分4.9 … 白天段=true`）
- **幂等**：`X-Idempotency-Key` 头（下单/取消），`idem_keys` 表存首次结果快照
- **审计**：create/accept/reject/cancel/reassign/start_trip/confirm_bill 全链路审计
- **轨迹**：热数据 Redis List（200点窗口）+ 行程结束刷盘冷数据；回放支持 stride 稀释 + 关键事件
- **缓存**：订单详情 Redis 缓存，状态变更事件精准失效
- **WebSocket**：订单状态/司机位置经事件总线 → Hub 定向推送到 `driver-{id}` / `user-{id}`

### 工单15 司机接单（接乘客&接到乘客）
- Redis 维护司机状态，上线写 `driver:status` + GEO 登记，下线移出派单池
- 订单创建后 GEO 取候选 → 按得分前 5 名定向 WS 推送（含预估金额）+ Stream 广播
- **并发防重**：`UPDATE ride_orders SET status='accepted', driver_id=? WHERE id=? AND status='pending' AND driver_id=0`，`RowsAffected==0` → 返回"订单已被他人接走"（测试用例3通过）
- 接乘客流程：到达上车点（arrived）→ 接到乘客（picked_up）

### 工单16 行程开始&确认账单&取消订单
- 行程开始：记录开始时间/地点，启动计费，司机状态 → ongoing 同步乘客端
- 到达目的地：停止计费，生成账单明细（见计费规则），司机恢复 online
- 确认账单：`ConfirmedAt` 落库，订单 → billed 提交结算；异议上报接口
- 乘客取消：按取消时间点计算补偿——行程开始前固定 ¥5 空驶费；开始后 `起步价+已行驶里程×1元/km`（上限¥50）；实时 WS 通知司机（含原因与补偿）；司机立即恢复可接单
- 修改目的地/乘车点：重算预估价，同步司机端

**计费规则**：白天起步 ¥13/3km、里程 ¥2.3/km；夜间（22:00~7:00）¥16.8、¥2.76/km 且加价 20%；
时长费 ¥0.5/min、等待费 ¥0.5/min、高速费实报；雨天浮动：黄色预警 +10%、橙/红 +15%（工单10联动）。

### 工单17 接单大厅
- `GET /orders/list`：Redis GEO 半径检索待接单 → 状态过滤 → 筛选（minFare/minScore/maxDistanceKm）
  → 排序（distance/fare/score）→ 分页；条目含经纬度与距司机距离（地图 Marker 直接可用）
- **抢单确定性**：DB 条件更新原子性 + 事务内二次校验；同一订单并发抢，只有一个成功，其余收到"订单已被他人接走"
- 拒单：记录原因与时间 → 重新触发派单（重新 GEO 推送其他司机）

### 工单10 AI 智能出行助手
- **Coze 客户端**：`COZE_API_TOKEN`/`COZE_BOT_ID` 环境变量配置（不硬编码密钥），未配置降级本地策略引擎
- **Function Calling**：
  - `calculate_rain_route`：输入 origin/destination/avoid/preference/rainfall，输出多条路线
    `{distance, duration*rain_delay_factor, risk_level, risk_score, alternative}`，按 risk_level 升序；
    risk_score 依据途经未清除积水点深度累加（`calculate_flood_risk`），下穿隧道规避加分
  - 天气预警回调：发布预警（yellow/orange/red）→ 事件总线推送在线用户；影响量化（等待+8min、费用+15%）
- **避雨点**：GEO 200 米检索带顶棚位置，含 ¥5 专属券与 15 分钟免费等待
- **积水上报**：更新 300 米内途经订单 → WS 推送司机（提前变道/备选路线）→ 自动发 ¥10 绕行补偿券
- **红色预警安全校验**：驾龄>5年方可接单，建议四驱优先+行程自动分享紧急联系人

### 工单19 WebSocket 并发重构（数字人会话）
- **统一协议**（字段不得增删）：`{"role","type","content","timestamp"}`，type ∈ text/audio/event/control
- **会话状态**：每连接独立（上下文、normal/immersive 模式、生成中/播放中标志），互不串线
- **事件序列**：`start_speaking` → 流式 text 分片 → `stop_speaking` → `dialog_end`
- **打断**：`control/interrupt` 立即 cancel 生成链路 goroutine，之后不再推送旧数据；沉浸模式支持插话
- **防强踢**：同账号多连接并存（byUser 映射），旧连接不被新连接断开
- **断线**：读超时（60s 心跳窗口）识别异常断线 → 清理会话并终止生成 goroutine（防泄漏）
- Coze 未配置时本地回声策略保证全链路可测（`cmd/wstest` 验证通过）

### 工单20 代码审查 Skills
- `cursor-skills/code-review/SKILL.md`：复制到 `.cursor/skills/`（或 `.trae/skills/`）生效
- 斜杠命令：`/review`（未提交变更）、`/review <path>`、`/review --strict`
- 四维审查（正确性/安全/性能/可维护性）+ 阻断/严重/建议三级判级 + Markdown 报告模板

## 四-B、新增工单 08/09/12/13/14/18 实现要点

### 工单08 Go 后端性能分析工具链
- **pprof**：`perf.RegisterPprof(r)` 挂载到 `/debug/pprof`，**全部分析端点经 `JWTAuth + RequireAdmin`**，
  防止 CPU/Heap/Mem/Block/Goroutine 等敏感 Profile 被未授权访问（验收：未鉴权访问返回 401）。
- **Prometheus**：`perf.Init()` 注册 `ride_http_requests_total`、`ride_http_request_duration_seconds`、
  `ride_runtime_goroutines`、`ride_runtime_heap_inuse_bytes`、`ride_runtime_gc_total`；
  中间件 `perf.RequestMetrics()` 采集每请求 QPS/时延，暴露于 `/metrics`（无需鉴权，供监控面板拉取）。
- **expvar / runtime/metrics**：`startRuntimeCollector()` 每 5s 将 GC 次数、堆内存、goroutine、分配速率
  写入 `expvar`（如 `runtime_gc_total`、`runtime_heap_inuse_bytes`），与 Prometheus 双写。
- **gops**：`main` 中以 `import _ "github.com/google/gops/agent"` + 环境变量 `GOPS_ENABLED=1` 启用，
  实时进程状态查询（默认关闭，零侵入）。
- 采样对业务影响极低（均为旁路采集），配置化程度高。

### 工单09 GVA 框架能力（平台管理）
- **轻量任务注册表（替代 XXL-JOB）**：`service/jobmgr.go` 内置 3 个示例任务
  `cleanup_expired_orders` / `redispatch_timeout` / `sos_reminder`，支持：
  - 在线参数更新（即时生效，落 `job_audits`）
  - 立即执行（管理员触发，记录耗时与结果）
  - 审计历史（`ListJobAudits`，可按 `jobName` 过滤）
  - 任务 `Run` 为 `func` 字段，JSON 序列化以 `json:"-"` 排除，避免 `c.JSON` 编码失败。
- **动态菜单**：`model.Menu`（parentID 树形），`buildMenuTree` 按 `sort` 构建菜单树，支持后台新增/更新。
- **结构化审计**：`model.JobAudit` + 操作审计 `order_audits`，`/audit-logs` 分页可追溯权限拦截点与操作记录。
- **多数据源工厂**：`pkg/datasource.Manager`（`Init/Primary/Replica/WithDB/FromCtx`），按 context 主从路由，
  便于后续读写分离；当前以单库默认实现，接口已就绪。

### 工单12 乘客端：登录 & 注册 & 账户信息
- **短信验证码登录**：`POST /auth/sms-code`（发送，`purpose=login|reset` 区分场景，本地返回 `devCode` 便于联调）、
  `POST /auth/sms-login`（校验码换 token）；`POST /auth/reset-password`（验证码重置密码）。
- **账户信息**：`GET/POST /me/profile`（昵称/头像/余额/积分/安全）、`POST /me/password`（改密码）。
- **常用地址**：`/me/addresses` GET/POST/PUT/DELETE（含默认地址标记）。
- **支付方式**：`/me/payments` GET/POST/DELETE（账号脱敏返回 `****0001`）。
- **帮助与反馈**：`POST /me/feedback`（type/content/contact）。
- **行程记录**：`GET /me/orders`（乘客历史订单，按时间倒序）。

### 工单13 乘客端：实时打车
- **附近司机地图**：`GET /drivers/nearby?lng&lat&radiusKm`（GEO 半径检索在线司机，返回距离/车牌/评分/在线状态）。
- **司机详情**：`GET /drivers/:id`（姓名/评分/在线状态/车辆）。
- **紧急求助 SOS**：`POST /sos`（orderNo/lng/lat/address）→ 创建 `SOSAlert` 并发布 `EvSOS` 事件通知管理员/司机
  （与工单01 的 `POST /sos/trip` 行程求助区分，避免路由冲突）。
- 复用常用地址、行程分享（工单01）、优惠券入口（工单07）。

### 工单14 乘客端：支付 & 评价 & 打赏 & 取消管理
- **打赏**：`POST /ride-orders/:orderNo/tip`（金额即时到账司机账户 `Balance`）。
- **发票**：`POST /ride-orders/:orderNo/invoice`（electronic/paper，申请/状态）。
- **匿名评价 + 审核**：`POST /ride-orders/:orderNo/review`（5星+评论+匿名）→ `RideReview` 默认 `pending`，
  管理员 `POST /ride-reviews/:id/approve|reject` 审核通过后公开，并更新司机 `ReviewCount`/服务评分。
- **取消滥用限制**：`CancelRecord` 记录取消行为，供风控统计（与工单11 取消补偿联动）。
- **多渠道支付**：`PaymentMethod` 支持 alipay/wechat/card 等多方式管理。

### 工单18 数字人 Coze 智能体
- 复用工单19/10 的 WS 会话与 Coze 客户端，新增 **Coze 代理 REST 接入点**（`/ai/chat` 已支持，未配置降级本地）。
- `GET /ai/digital-human/status` 暴露 `cozeAvailable` / `mode`（local/coze），便于前端判断能力。
- 前端联调骨架：`web/digital-human.html`（WS 连接 + TTS + 打断 + token 输入）。
  **Live2D 渲染为前端 Node 项目，超出 Go 后端范围，已文档说明**。
- `WsDigitalHuman` 支持从 query `?token=` 或 Header 透传 token（浏览器原生 WebSocket 无法自定义 Header）。

**测试中发现并修复的问题**：
1. 派单配置回滚只减版本号未恢复旧值 → 增加快照表，回滚真正恢复配置
2. `DATE_ADD`（MySQL 专用）跨库不兼容 → 参数化时间窗
3. 轨迹热数据反序列化 json tag 非法 → 修正字段标签

**新增工单集成测试**（`test_new.ps1`，覆盖 08/09/12/13/14/18，实测通过）：
- 工单12：短信验证码发送（返回 devCode）→ 验证码登录换 token → 验证码重置密码 ✓
