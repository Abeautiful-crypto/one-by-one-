# 网约车管理系统 — 代码说明文档

> 项目依据 7 份任务工单开发（全栈开发-网约车-01 ~ 07），使用 Go 语言实现。
> 所有代码注释中均标注了对应的工单编号。

---

## 1. 项目概述

本项目是一套网约车后台管理系统，覆盖 **顺风车管理、班车管理、财务管理、订单管理、人员管理、数据分析、营销管理** 七大业务模块，满足各工单的功能与验收要求（实名制、站点排序规则、批量退票策略、RBAC 多角色、数据分析口径、优惠券规则等）。

## 2. 技术栈

| 分类 | 技术 | 说明 |
|---|---|---|
| 开发语言 | Go 1.26 | 静态编译、高并发 |
| Web 框架 | Gin v1.10 | RESTful API（工单07：API 设计要求） |
| ORM | GORM | 默认 SQLite（纯 Go 驱动，免安装直接运行），生产可切 MySQL（`DB_DRIVER=mysql`） |
| 认证 | JWT（golang-jwt/v5）+ bcrypt | 无状态登录认证、密码加密存储 |
| 权限 | RBAC 角色模型 | 多角色绑定（工单05）、接口级角色校验中间件（图片要求：多角色管理模型、独立管理界面） |
| 参数校验 | go-playground/validator（gin binding） | 工单04：校验应能使用 Validator 进行 |
| 设计模式 | 策略模式 + 工厂模式 | 优惠券计算（工单07）、退票取消费政策（工单04）、策略工厂 |
| 缓存 | 接口化内存缓存（可替换 Redis） | 工单07：缓存机制，减少优惠券列表查询压力 |
| 安全 | HTTPS（可选 TLS）、审计日志、操作日志 | 工单01/03/04：加密传输、审计追踪 |
| 异步处理 | goroutine + 任务表 | 工单01：异步导出、账单异步生成 |

## 5. 各工单实现要点

### 工单01 — 顺风车管理（`trip.go` / `driver.go` / `service/export.go`）
- **实名制注册**：`POST /api/v1/auth/register` 强制校验真实姓名 + 身份证号（validator len=18）。
- **证件上传验证**：`/driver/docs`（身份证/驾驶证/行驶证），管理端 `/driver-docs/:id/audit` 审核，通过后司机实名状态生效。
- **行程发布**：起终点输入/选择、即时请求与未来预约、特殊需求（婴儿座椅/宠物）、紧急求助 `POST /sos`（一键联系警方/客服）。
- **行程分享**：生成带过期时间的分享 token，`GET /share/trip/:token` 免登录查看并统计浏览次数。
- **双向评价**：乘客评司机（`POST /reviews`）自动更新司机服务评分均值；司机评价乘客走同一 Review 表（role 区分）。
- **司机配置**：车辆品牌/型号/颜色/车牌/外观照片备案；年检、保险到期提醒接口（30 天内到期提醒）。
- **性能优化（验收标准）**：导出走异步任务（分页查询 + 逐步写文件，避免内存溢出）；`ExportTask` 记录谁在何时导出什么（操作日志/审计）；失败原因写入 `error_msg`（异常日志）；下载走 HTTPS。

### 工单02 — 班车管理（`route.go` / `service/station.go`）
- 线路管理：名称、起点、终点，途经站点列表（站点位置 + 预计到达时间）。
- **上下车站点排重**：同一线路同名站点 + 同类型不允许重复（`SortStations` 校验，违例返回 400 明确提示）。
- **站点自动排序（验收标准）**：按录入的距起点分钟数升序排序；上车站点第一条时间强制为 0。
  例：A→B 20min、A→C 40min、A→D 30min ⇒ 排序结果 **A(0) B(20) D(30) C(40)**（已实测验证）。
- 排班：班次关联线路/车辆/司机，发车时间（前端以日历形式展示）、票价、座位数。

### 工单03 — 财务管理（`finance.go` / `service/finance.go`）
- **交易明细**：交易号、订单号、金额、支付方式、交易时间；支持日期范围 / 订单号 / 支付方式 / 收支方向灵活查询。
- **收支对账** `GET /finance/reconcile`：订单应收 vs 流水收入-支出，输出差额与未处理异常数（并发一致性由事务保障）。
- **自动账单**：日/周/月账单，异步 goroutine 生成，任务状态可查询。
- **异常处理**：支付流水落库时自动检测**重复扣款**（同订单多笔成功支付）与**金额不符**（支付额≠应收额），生成 Anomaly 记录；管理端可标记修正。
- **争议解决**：用户提交争议 → 客服处理（processing/resolved/closed），全程留痕。

### 工单04 — 订单管理（`order.go` / `refund.go` / `service/refund_policy.go`）
- 订单统一包含**班车和顺风车**订单，通过 `orderType` 筛选区分。
- **订单状态机**：待接单 → 已支付 → 进行中 → 已完成 / 已取消（记录取消原因）；每次流转写 `OrderStatusLog` 历史变更记录。
- **退票管理**：在线申请（选择取消原因）→ **自动审核**（按预设取消费规则立即反馈）→ 复杂情况**人工复核**（approve/reject/manual，支持人工调整退款金额）→ 状态跟踪列表。
- **取消费政策（策略模式）**：
  - 不可抗力 → `FullRefundPolicy` 全额退款；
  - 距发车 >24h 全额退；2~24h 收 50% 取消费；<2h 不退款（部分退款逻辑）。
- **批量退票**：`POST /refunds/batch` 支持批量 ID + 单个排除（全选/反选由前端配合）、按政策自动计算应扣款项、批次号追踪；分批处理保障性能。
- **Validator 校验**：所有入参结构体使用 binding 标签。
- **支付安全**：支付信息传输启用 HTTPS（`TLS_ENABLED=true`），支付流水写入财务模块并触发异常检测。

### 工单05 — 人员管理（`personnel.go` / `service/import.go`）
- 人员分三类管理：员工管理（企业内部）、司机管理（顺风车司机）、用户管理（乘客），统一 User 表 + 多角色。
- **角色**：admin、调度员（dispatcher）、验票员、联系人员、班车司机、接送司机、顺风车司机、乘客（首次启动种子初始化）。
- **调度员独立界面**：调度类接口（线路/排班）要求 `RequireStaff`，管理端前端可按角色渲染独立界面；调度员独立账号登录。
- **批量操作**：批量启用/禁用/删除（事务保证）。
- **数据导入**：CSV/JSON 文件导入；**格式检查**（手机号/身份证/邮箱正则）、**唯一性验证**（库内 + 批内手机号/身份证排重）、**详细错误报告**（逐行列出字段、原因、修改建议）。
- 关键字搜索（姓名/手机号/用户名/邮箱）+ 分页（工单01 分页处理要求）。

### 工单06 — 数据分析（`analytics.go` / `service/analytics.go`）
- **订单量分析**：按日/周/月统计总量、订单增长率（与上一周期对比）、平均订单值、**有效订单总数**、**无效订单总数**（取消）、**使用优惠券订单总数**。
- **转化率分析**：转化率 =（产生购买行为的客户人数 ÷ 所有注册人数）× 100%；输出五步漏斗（访问→选择服务→下单→支付→完成，前段基于 UserVisit 埋点）与取消原因分布。
- **复购周期分析**：首次订单时间、后续订单时间、复购次数（除首单外订单数）、平均/最长/最短复购周期（应用层计算，兼容 SQLite/MySQL）。
- **行为埋点**：`POST /analytics/track` 上报页面访问、点击、停留时间（异步落库）。
- 响应时间：SQL 聚合 + 索引，满足 5 秒内响应验收标准。

### 工单07 — 营销管理（`coupon.go` / `service/coupon_strategy.go`）
- **优惠券类型（策略模式 + 工厂模式）**：
  - 折扣券（按比例 + 最高优惠上限）、现金券（固定抵扣）、免费乘车券（最高免费额度封顶）；
  - `GetCouponStrategy(type)` 工厂获取策略，新增类型只需注册新策略。
- **适用范围**：城市/区域、车型（经济型/豪华型）、有效期（`required,gtfield` 校验止晚于起）。
- **使用规则**：最低消费要求、**不可叠加**（一单仅可核销一张）、订单取消/退款时优惠券状态冻结处理预留。
- **发放**：手动发放（管理端指定用户）、**自动发放规则**（new_user 近 7 天注册 / high_consumer 累计消费 Top100）、库存扣减 + 每人限领一张。
- **推广发码 + 推荐奖励**：批量生成优惠码，用户领取后双方得券（inviter 机制）。
- **删除校验**：已被领取/使用的优惠券禁止删除（校验 UserCoupon 引用计数）。
- **收藏功能**、关键词搜索（名称/描述/类型模糊匹配）+ 缓存（30s TTL，可替换 Redis）、索引优化。

## 8. 并发与性能设计

- **并发控制**：下单扣减座位、优惠券库存、退款流水均在 `DB.Transaction` 中执行，SQLite/MySQL 均以事务保证一致性（工单03/04：并发场景数据一致性）。
- **分页处理**：所有列表接口分页；导出任务分页查询 + 流式写文件（工单01：避免内存溢出）。
- **异步任务**：审计日志、账单生成、异常检测、导出均为异步，不阻塞前台（工单01）。
- **缓存**：优惠券列表 30 秒 TTL 缓存，`Cache` 接口可直接替换 Redis 实现（工单07）。
- **响应时间**：分析类接口 SQL 聚合 + 索引，满足 5 秒验收；关键接口配合压测工具（如 JMeter，工单03/04 出物要求）验证 QPS 与平均响应时间。
