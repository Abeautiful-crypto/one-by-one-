# 网约车项目代码审查 Skill（工单20）

在 Cursor/Trae 中将本目录放入 `.cursor/skills/`（或 `.trae/skills/`）即可生效。
用户输入 `/review <文件|目录|git diff>` 或自然语言"帮我代码审查"时，按以下流程执行。

## 审查流程

1. **确定范围**：未指定则默认审查 `git diff HEAD` 变更文件；指定目录则遍历 `*.go`。
2. **四维检查**（逐文件执行）：

### 维度1：正确性
- 状态机流转是否原子（如抢单必须使用条件更新 `WHERE status=?`，禁止先查后改）
- 幂等：下单/取消/支付类接口是否有幂等键保护
- 并发：共享状态是否有锁保护；goroutine 是否会泄漏（context 取消）
- 错误吞没：`err` 被忽略、`recover()` 滥用

### 维度2：安全
- SQL 注入（拼接 SQL）、XSS（未转义输出）
- 越权：资源访问是否校验属主（订单只能被本人/相应司机访问）
- 密钥硬编码（Coze Token、JWT Secret 必须来自环境变量）
- WebSocket：Origin 校验、鉴权、单连接读上限

### 维度3：性能
- N+1 查询（循环内查库）
- 缺索引的高频查询字段（对照 model tag）
- Redis 热点 key、无 TTL 的缓存
- 大事务（事务内做 HTTP 调用）

### 维度4：可维护性
- 魔法数字/字符串（订单状态必须用 model 常量）
- 重复代码（>3 处相同逻辑需提取）
- 命名与注释（工单编号注释是否齐全）

## 输出格式

```markdown
# 代码审查报告
**范围**：<文件/目录>  **时间**：<ISO8601>

## 摘要
- 阻断项: N  严重: N  建议: N

## 问题清单
| # | 级别 | 文件:行 | 维度 | 问题 | 修复建议 |
|---|------|---------|------|------|----------|

## 通过项
- <检查过且无问题的要点>
```

## 判级标准
- **阻断**：越权、SQL 注入、资金计算错误、并发丢更新
- **严重**：goroutine 泄漏、错误吞没、缓存不一致
- **建议**：命名、注释、重复代码

## 触发命令
- `/review` — 审查未提交变更
- `/review <path>` — 审查指定文件或目录
- `/review --strict` — 额外检查工单编号注释完整性
